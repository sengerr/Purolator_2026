## Measured differences

Spec values that disagree with what the API answered in this repository's live runs.
The collections keep the measured value; everything else follows the spec.

| Field | Difference |
|---|---|
| `outboundShipment.crossBorderInformation.nonDocumentsInformation.businessRelationship` | The spec lists TRUE \| FALSE, but Certification accepted "related" / "NotRelated" (200, 2026-10-06) and rejected "FALSE"; the request keeps the measured value. |
| `outboundShipment.senderInformation.streetAddress[]` | Estimate only: the spec types each line as {"Address": "..."}; plain strings were accepted in every Certification estimate (2026-10-06), so the request keeps strings. |
| `outboundShipment.receiverInformation.streetAddress[]` | Estimate only: the spec types each line as {"Address": "..."}; plain strings were accepted in every Certification estimate (2026-10-06), so the request keeps strings. |
| `outboundShipment.shipmentInformation.serviceId` (RMS) | `PurolatorExpressReturn` / `PurolatorGroundReturn` are not in the outbound enum but were accepted on every RMS / return request (200, 2026-10-06). |
| `documentCriteria[].documentType[]` | `COSBillOfLading` is not in the enum; the requests that send it are kept as defect evidence and fail with `9001-311`. |
| Locator headers | The spec marks `x-origin-verify` and `access-control-allow-origin` required; Certification answered 200 without them. |
| `Language` header | Collections send lower-case `en` / `fr` (case-insensitive per the spec; the FR tooling keys on `fr`). |
